# Remotion interpolate() と Easing で速度プロファイルを設計する

- 題材ID：web-remotion-interpolate-easing
- 媒体：Web（公式ドキュメント）
- 出典：Remotion公式 `interpolate()` https://www.remotion.dev/docs/interpolate ／ `Easing` https://www.remotion.dev/docs/easing （2026-11-26にMuseが直接読んで確認）
- 分野：AI動画編集の手法／Remotion
- 対象ゴール：目標1（リリックビデオ再現）
- 選んだ理由：再現制作で「線形補間では不十分」と実測で判明した区間（A2背景ドリフト local 38〜44、増分が加速型）があり、補間の既定動作と区間ごとのイージング指定を公式仕様で裏取りする必要があったため。

## テクニック・手法の概要
- `interpolate(frame, inputRange, outputRange, options)` は入力範囲を出力範囲へ写す関数。既定の easing は `(x) => x`、つまり**何も指定しなければ純粋な線形（等速）**になる（①Muse直接確認／裏取り済み）。
- easing は「隣り合うキーフレーム間の区間（active segment）」の中で正規化された進み具合を曲げる。複数キーフレームの場合は **easing を配列で渡して区間ごとに別々の曲線**を指定できる（配列の長さは `inputRange.length - 1`）（①／裏取り済み）。
- 動きの速度プロファイルは easing の形そのもの：`quad` は `f(t)=t*t`（加速）、`cubic` は `f(t)=t*t*t`（より強い加速）、`poly(n)` は n 乗、`bezier(x1,y1,x2,y2)` は CSS の transition-timing-function と等価な3次ベジェで自由に設計できる（①／裏取り済み）。
- 範囲外の扱いは既定が `extend`（範囲を超えて伸び続ける）なので、区間の端で止めたい場合は `extrapolateLeft/Right: 'clamp'` を明示する（①／裏取り済み）。
- `Easing.spring()` は interpolate 用のバネ easing（damping 既定10、mass 既定1、stiffness 既定100、30フレームで測った曲線を正規化）。`allowTail: true` で区間終了後もバネの尾を引き継げる（①／裏取り済み）。通常の `spring()` API とは別物である点に注意。

## 再現手順（設定値つき）
1. 実測した点列がある場合は、まず点列そのものをキーフレームにする：`interpolate(frame, [38,39,40,41,42,43,44,45], [0,1.1,3.3,6.5,11.1,17.1,24.7,34.0], {extrapolateLeft:'clamp', extrapolateRight:'clamp'})`（数値はA2ドリフト実測の例。点列方式は easing の当て推量より優先する）。
2. 点列がなく曲線で近似する場合は、加速型なら `easing: Easing.in(Easing.quad)` または `Easing.in(Easing.cubic)`、減速型なら `Easing.out(...)`、加速→減速なら `Easing.inOut(...)` を使う。
3. 区間ごとに性格が違う場合は配列で渡す：`easing: [Easing.out(Easing.cubic), Easing.in(Easing.cubic)]`。
4. 検証は必ずフレームごとの増分（速度プロファイル）を数値で出し、段差・停滞・中盤の速度低下がないか確認する（静止画照合だけでは動きの欠陥は捕まえられない、という既存の制作教訓と接続）。

## 必要なツール・機能（有料のものがあれば価格とともに明記）
- Remotion（既存の制作環境、そのまま利用可能。追加費用なし）

## AIについて分かったこと
- 生成AI／自動生成コードが「補間」と書いたとき、既定は線形であり、**速度の性格は明示しなければ等速になる**。AIに動きを頼む際は「何フレームで何px」だけでなく「増分がどう変化するか（加速／減速／等速）」まで指定しないと、実測とズレる動きが返ってくる（③Claudeの解釈／未検証・暫定：一般論としての適用は今後の試作で確認）。
- 逆に、実測点列をそのままキーフレーム化する方式は、easing の種類当てというAIの推測を挟まないため、再現精度の観点で最も確実な委任の形になる（③／未検証・暫定）。

## 金木さんへの応用
- A2ドリフトで採用した「実測点列への差し替え」は公式仕様上も正しい使い方（複数キーフレーム＋clamp）であることを確認した。今後の再現区間でも、①点列が取れる動きは点列方式、②取れない動きだけ easing 近似、の順で設計する。
- 文字の成長・背景移行など「長さ」だけでなく「速度の形」が問われる箇所では、試作依頼時に速度プロファイル（増分の列）を仕様に含める。
