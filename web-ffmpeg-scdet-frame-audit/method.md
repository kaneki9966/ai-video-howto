# FFmpeg scdet でフレーム間差分を全数測定する（全フレーム監査の補助）

- 題材ID：web-ffmpeg-scdet-frame-audit
- 媒体：Web（FFmpeg公式メーリングリストのパッチ文書＋実務ガイド2件）＋ローカル実機確認
- 出典：FFmpeg公式パッチ文書 https://ffmpeg.org/pipermail/ffmpeg-devel/2019-October/251173.html ／ 実務ガイド https://www.ffmpeglab.com/articles/ffmpeg-scene-detection-automated-editing.html ／ https://www.ahosting.net/faq/ffmpeg-hosting/how-to-detect-scenes-silence-and-black-frames-with-ffmpeg.html （2026-11-26にClaudeが直接読んで確認）
- 分野：AI動画編集の手法／検証
- 対象ゴール：目標1（リリックビデオ再現）／両方
- 選んだ理由：再現の検収ルール「全フレームの差分測定＋差が大きいフレームの目視」を、手作業の位相相関だけでなくFFmpeg標準機能でも回せるかを確認するため。特に2フレーム級の短いイベント（白フラッシュ・暗転）の取りこぼし対策になる。

## テクニック・手法の概要
- `scdet` フィルタはフレームごとのメタデータとして `lavfi.scd.mafd`（フレーム間平均絶対差）、`lavfi.scd.score`（シーン変化スコア）、`lavfi.scd.time` を全フレームに付ける（①Claude直接確認／裏取り済み：公式パッチ文書と実務ガイド2件で一致）。
- 閾値 `threshold`（短縮形 `t`）の既定は 10、範囲は 0〜100 で、公式文書の推奨域は 8.0〜14.0。閾値を超えたフレームでシーン変化としてログとメタデータが出る（①／裏取り済み）。
- `sc_pass`（短縮形 `s`、既定 0）を有効にするとシーン変化フレームだけを次段へ通せる（①／裏取り済み）。
- 似た別手段 `select='gt(scene,0.4)'` の `scene` は 0〜1 の尺度で、実務ガイドの推奨域は 0.3〜0.5。**scdet の 0〜100 尺度と混同しないこと**（①／裏取り済み：尺度の違いは出典間で明確に区別されていた）。
- 検出フィルタの出力は stderr／メタデータ側に出るため、`-f null -` と組み合わせて読むのが実務ガイド共通の型（①／裏取り済み）。

## 再現手順（設定値つき）
1. 全フレームの差分列を出す：
   `ffmpeg -hide_banner -i input.mp4 -vf "scdet=threshold=10,metadata=print" -an -f null -`
   → 各フレームの `lavfi.scd.mafd` と `lavfi.scd.score` が並ぶ。これが「変化マップ」のFFmpeg版になる。
2. カット／フラッシュ候補だけ拾う場合は閾値を調整する：まず既定の `threshold=10` で回し、取りこぼしが多い素材では 8、誤検出が多い素材では 14 まで上げる（公式推奨域 8.0〜14.0 の範囲内）。
3. 黒フレーム区間（暗転の検出）は別フィルタ `blackdetect=d=0.5:pix_th=0.1` を併用する（実務ガイドの型。今回の再現では暗転カーブの確認に使える）。
4. ローカル実機確認（2026-11-26、①Claude直接確認／裏取り済み）：この環境の ffmpeg で `ffmpeg -h filter=scdet` が threshold 0〜100・既定10・sc_pass を表示し、参考動画の冒頭3秒に上記コマンドを実行して全フレーム分の mafd／score が出力されることを確認した。冒頭の黒い区間では mafd=0.000 が続いた。

## AIについて分かったこと
- 「映像を数値で測る道具」は生成AIではなく古典的な信号処理フィルタの側にあり、**閾値の尺度（0〜1 と 0〜100）が手段ごとに違う**。AI（や人間）がコマンドを組み立てる際に最も起きやすい事故は、この尺度の取り違えである（③Claudeの解釈／未検証・暫定）。
- mafd のような全フレームの数値列があれば、「変化があったか」をAIの文章観察に頼らず機械判定に寄せられる。文章観察同士が矛盾した過去の経緯（書体・冒頭の食い違い）への対策として、数値列を正本側に置く設計が有効（③／未検証・暫定）。

## 検証メモ
- 出典間で食い違った点：閾値の推奨値そのものは手段が違うため単純比較できない（select の scene は 0.3〜0.5、scdet は 8〜14）。混同すると全く検出できない／過検出になるため、上記のとおり尺度を分けて記録した。
- 確認できなかった点：再現プロジェクトの本番監査（全区間）で scdet の候補化が既存の監査JSONとどれだけ一致するかは未実施（**未実証**）。冒頭3秒の動作確認のみ完了。
